# Maintenance log

Everything that changed after the testimonials section was added, in order. Each entry names the commit that made it.

By Claude in a second Claude Code session, separate from the headless run that wrote the change. Checked: the diff file by file, Studio validation on the drafts, drafts at 1440 and 390 px, published pages before and after, the four Presentation checks on the deployed site. Changed:

## Rosette as a static file, [4c95048](../../../commit/4c95048)

The rosette became a static SVG generated by `web/scripts/rosette-svg.mjs`, which took the page from 850 KB of HTML to 150 KB. The wordmark seal was then redrawn inline with heavier rings so it reads at 28 px ([2695314](../../../commit/2695314)).

## Fixes from a fresh review, [c6a9c67](../../../commit/c6a9c67)

- The rule for a CTA without a main button and the rule for a statement card missing an amount now block publishing; zero counts as an amount; amounts are capped at 999 billion.
- A quote or a name made only of spaces is rejected and never rendered.
- A testimonials section with no published quote renders nothing instead of a lone heading.
- Buttons link to pages instead of a placeholder mail address.
- The seed creates the three testimonials and both testimonials sections.
- Long amounts shrink to fit the statement card at any width.
- No default Sanity project: missing variables stop the Studio and the build.
- Social preview image, MIT licence.
- The video was re-cut with the current wordmark and now ends on the testimonial type ([52935d4](../../../commit/52935d4)).

Note on validation levels: outside the Studio, `sanity documents validate` adds its own unknown-fields check to object-level rules with `.warning()`, which also downgrades their custom rules to warnings in the CLI report. In the Studio they block publishing; the release checks test them there.

## Safer checks and a narrower README, [dc665c3](../../../commit/dc665c3) and [5a53171](../../../commit/5a53171)

- Check scripts never touch existing work: they refuse to run if any page or testimonial has a draft, write only to their own test documents (`solution-check-*`, `testimonial-check-*`), delete them at the end with a revision check, and read `SANITY_DATASET`. The Presentation checks now run on a temporary test page instead of the landing page.
- Every check declares its expected result; the scripts exit non-zero on any failure, and `run_all_checks.py` writes a report per verified commit in `docs/checks`.
- New blocked cases: a second hero that is valid on its own, a button label without a destination, slugs with `/`, `?` or `#`. New allowed cases: a stale external address hidden by an internal link, an out-of-range amount hidden by the Plain layout (`context.hidden` with `Rule.skip()`, supported by the locked Sanity 6.18.0).
- One path builder, `web/lib/routes.ts`, for the header, the buttons and Presentation; the slug must match it.
- A "Draft preview · Exit preview" control outside the Studio.
- The currency amount is announced to screen readers; the video dialog matches the video's 8:5 ratio.
- The seed is documented as a reset, with a `--bootstrap` option that only creates missing documents.
- The README now quotes one real MCP exchange from the session log and labels the rest as the author's account.
- Every check passed on the deployed site for 5a53171: [docs/checks/checks_5a53171.json](checks/checks_5a53171.json).
